# 会员支付系统场景清单

更新日期：2026-06-10

本文用于梳理会员、订单、支付、兑换码、退款、赠送、永久升级等场景，方便推广前检查风险。自动化测试入口：

```bash
npx tsx scripts/test-membership.ts
npx tsx scripts/test-wechat-payment-amount.ts
```

## 当前结论

主流程和核心边界已覆盖自动化测试。当前本地 `scripts/test-membership.ts` 覆盖 40 项场景，全部通过。

仍需线上持续观察的部分是支付平台真实回调、邮件到达率、服务器压力和人工后台操作记录。这些依赖真实环境，不适合只靠本地脚本下结论。

## 已有逻辑保护

| 风险 | 保护位置 | 当前处理 |
| --- | --- | --- |
| 前端篡改价格 | `/api/membership/order/create` | 服务端按套餐和兑换码重算金额 |
| 微信回调金额不一致 | `/api/membership/notify` + `validateWechatPaidAmount` | 拒绝开通并记录异常事件 |
| 微信回调非成功状态 | `/api/membership/notify` | 忽略并记录 WARN |
| 回调订单不存在 | `/api/membership/notify` | 返回失败，让支付平台重试 |
| 已取消/已退款订单收到回调 | `applyPaidMembershipOrder` | 返回 `bad_status`，不改权益 |
| 邮件发送失败 | 回调内异步发送 | 不影响权益开通 |
| 同一会员并发回调 | `applyPaidMembershipOrder` | 事务中锁会员行，串行计算权益 |
| 后台删除/归档订单 | 管理端 | 归档不影响权益状态，可恢复管理视图 |

## 后续重点监控

这些场景需要线上日志和真实支付环境配合观察：

1. 微信真实回调的延迟、重复频率、金额异常频率。
2. 支付成功但邮件失败的比例。
3. 推广高峰期待支付订单数量增长。
4. 兑换码被大量尝试时的失败原因分布。
5. 管理员手动赠送、撤销、退款之后的会员咨询情况。
6. 新产品上线后的产品隔离和全站通访问范围。
7. 数据库连接数、接口耗时、502/504 等服务异常。

## 推广前建议

1. 推广当天打开后台「会员订单」和「事件日志」观察。
2. 保持待支付订单清理脚本定期运行。
3. 出现支付咨询时先查订单号，再查事件日志，再查会员权益。
4. 新增产品前，先补一条产品隔离测试，再上线售卖。
5. 修改套餐价格、兑换码规则、退款逻辑后，先跑完整测试脚本。
